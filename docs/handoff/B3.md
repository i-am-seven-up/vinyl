# Handoff B3 — engine playback

B3 bổ sung engine trên UI B2; L3 vẫn dành cho playlist ở B4.

## Luồng file

- `player/FadingPlayer.kt`: subclass framework gom play/pause vào một fade job; future của Media3 phản ánh thao tác đang chờ. Seek/đổi queue/stop/release hủy fade, khôi phục volume. Không thêm player thứ hai.
- `player/PlaybackService.kt`: sở hữu ExoPlayer, session, logger, coroutine lifecycle; listener chụp snapshot, writer transaction và timer 5 giây chỉ khi isPlaying. Restore bất đồng bộ; callback thêm bài chờ restore để không ghi đè lựa chọn mới bằng queue cũ.
- `player/PlayEventLogger.kt`: logic thời gian thuần, inject monotonic/wall clock, expose event snapshot read-only. Khi item transition phải checkpoint ngay để lưu event vừa kết thúc.
- `player/PlaybackStateStore.kt`: đọc snapshot, kiểm tra URI trên IO, filterPlayback thuần ánh xạ occurrence/index/position.
- `shared/database/PlaybackDao.kt`: entity snapshot/queue/event và read/write transaction. `VinylDatabase.kt`: schema v2 + MIGRATION_1_2. AppContainer chỉ nối dependency; service lấy store/DAO từ container.
- `player/PlayerController.kt`: đọc storage error từ session extras và đồng bộ UI. B2 command/UI vẫn dùng được.

## Hợp đồng

`PlaybackStateStore.findPlayback()` chỉ đọc, trả nullable SavedPlayback. Queue rỗng khi không còn URI truy cập được. `filterPlayback(saved, canRead)` không sửa input.

`PlaybackDao.savePlayback(snapshot, queue, events)` là suspend command Unit, transaction toàn bộ; lỗi ném về service và hiện trên UI, không đổi thành Boolean. `findPlayback`, `getQueue`, `getPlayEvents` chỉ đọc. Event ID ổn định trong một lượt nghe để checkpoint không nhân đôi row.

`PlayEventLogger.updatePlayback(mediaId, playing, isNewItem)` / `checkpoint()` là command Unit; `getEvents()` chỉ trả snapshot, không tăng thời gian ngầm. Logger không được lấy media position làm elapsed duration. Khi thêm flow/service caller khác, phải giữ checkpoint theo transition/pause và ghi có thứ tự.

## Chạy thử / làm tiếp

Theo [B3 TESTING](../b3/TESTING.md). Phát → seek → pause → mở lại sau process death: queue/vị trí còn và chưa phát tiếng. Xóa một file trước mở lại: bài còn lại được chọn an toàn. Khánh giữ UI B2, cải thiện giao diện độc lập với engine; chưa có màn History trong phạm vi B3.

B4 thêm playlist cần tăng schema lên v3 và migration 2→3, giữ MIGRATION_1_2; không destructive migration. Trước khi tạo FK tới songs, thay snapshot delete+insert của LibraryRepository bằng upsert/xóa bài mất theo ghi chú L1.

Giới hạn: checkpoint ~5 giây có thể mất khi process kill; shuffle flag giữ nhưng hoán vị không giữ. Bluetooth/fade máy thật/API 32 chưa kiểm tra. Force-stop không được xem là luôn tự resume. Tham chiếu [Media3 background/resumption](https://developer.android.com/media/media3/session/background-playback), API pinned 1.8.0.
